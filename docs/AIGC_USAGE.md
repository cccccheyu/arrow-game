# AIGC 使用记录

> 作业要求：记录至少 3 次具有代表性的 AIGC 使用过程，说明自己提出了什么要求、AI 完成了什么、实际效果如何，以及自己是否进行了修改。

本项目全程使用 **Qoder（Coding Agent）** 作为主要 AIGC 工具，辅以 **ChatGPT** 与 **DeepSeek** 进行算法讨论、代码审查与关卡设计验证。以下记录均来自真实开发过程。

## 记录 1：路径检测算法与边界处理

| 项目 | 内容 |
|---|---|
| **子任务** | 实现四方向路径检测，处理边缘箭头越界问题 |
| **借助何种 AIGC** | Qoder（Coding Agent） |
| **我提出的要求** | "实现一个函数 `is_path_clear(board, row, col, direction)`，判断箭头前方到边界之间是否还有其他箭头。要求：边缘箭头（如第 0 行朝上）不能发生数组越界错误。" |
| **AI 实现或提供了什么** | 生成了基于 `while` 循环的四方向检测代码，使用 `direction.delta` 元组统一处理四个方向，避免了 if-else 散落。 |
| **实际效果如何** | 基本可用，但初版在 `while` 条件中写成了 `r < rows` 而漏掉了 `r >= 0`，导致朝上/朝左的边缘箭头会进入负索引（Python 不会报错但逻辑错误）。 |
| **人工修改** | 将循环条件改为 `0 <= r < rows and 0 <= c < cols`，并补充了 5 个边界单元测试（T03 系列）验证。修改后所有测试通过。 |

**关键代码（修改后）：**
```python
def is_path_clear(board, row, col, direction):
    dr, dc = direction.delta
    r, c = row + dr, col + dc
    while 0 <= r < board.rows and 0 <= c < board.cols:
        if board.grid[r][c] is not None:
            return False
        r += dr
        c += dc
    return True
```

## 记录 2：关卡设计与可解性验证

| 项目 | 内容 |
|---|---|
| **子任务** | 设计 6 个手工关卡，确保每关都可通关 |
| **借助何种 AIGC** | Qoder + DeepSeek（交叉验证） |
| **我提出的要求** | "设计 6 个 5x5~7x7 的关卡，难度递增，每关 4~12 个箭头。要求：每关都必须存在至少一组通关顺序，不能出现死锁（如两个箭头互相阻挡）。" |
| **AI 实现或提供了什么** | Qoder 生成了 6 个关卡布局与声明的通关顺序；我另外用 DeepSeek 独立验证了每关的可解性。 |
| **实际效果如何** | 初版关卡 2 的声明顺序有误（`(2,4)v` 被 `(4,4)<` 阻挡，但我先点了 `(2,4)`）；关卡 6 出现了 `(2,6)v` 与 `(4,6)^` 互相阻挡的死锁。 |
| **人工修改** | 1) 调整关卡 2 的顺序为 `(4,1)→(4,4)→(2,4)`；2) 将关卡 6 的 `(4,6)^` 改为 `(4,6)v`，消除死锁；3) 编写了 `solver.py`（DFS 求解器）与 `test_levels.py`，对每关自动验证"声明的 solution 能通关"且"求解器也能找到解"。修改后 6 关全部通过自动化验证。 |

**验证脚本输出：**
```

L2 arrows= 6 solvable=True declared_ok=True
L3 arrows= 8 solvable=True declared_ok=True
L4 arrows= 8 solvable=True declared_ok=True
```

## 记录 3：碰撞反馈动画与粒子系统

| 项目 | 内容 |
|---|---|
| **子任务** | 实现箭头碰撞时的抖动反馈与成功飞出时的粒子特效 |
| **借助何种 AIGC** | Qoder（Coding Agent） |
| **我提出的要求** | "碰撞时箭头要沿垂直于方向的方向来回抖动并变红，持续约 0.45 秒；成功飞出时要有尾迹粒子和爆散粒子。使用缓动函数让动画更自然。" |
| **AI 实现或提供了什么** | 生成了 `ShakeAnimation`（衰减正弦波抖动）、`FlyAnimation`（ease-out-cubic 飞出）、`ParticleSystem`（爆散 + 尾迹）三个类，以及 4 种缓动函数。 |
| **实际效果如何** | 抖动动画初版 amplitude 太大（20px），看起来像"抽搐"；粒子初版没有 alpha 衰减，消失得很突兀。 |
| **人工修改** | 1) 将 amplitude 从 20 调到 8，并加入 `decay = 1 - t` 让抖动逐渐减弱；2) 给粒子加入 `alpha` 属性，按剩余寿命线性衰减；3) 飞行尾迹改为每帧只生成 2 个小粒子，避免性能问题。修改后动画流畅自然。 |

## 记录 4：DFS 自动求解器

| 项目 | 内容 |
|---|---|
| **子任务** | 实现 AI 自动求解当前关卡，用于演示模式与关卡可解性验证 |
| **借助何种 AIGC** | ChatGPT（算法讨论）+ Qoder（代码实现） |
| **我提出的要求** | "写一个求解器，输入棋盘状态，输出一组通关顺序。要求：能处理死锁（返回 None），能用于验证随机关卡的可解性。" |
| **AI 实现或提供了什么** | ChatGPT 建议用 DFS + 状态去重（visited 集合）；Qoder 生成了完整实现，包括 `solve()`、`count_solutions()`、`is_solvable()` 三个函数。 |
| **实际效果如何** | 初版没有状态去重，对于 12 箭头的关卡会重复探索相同状态，耗时较长；加入 visited 集合后，12 箭头关卡在毫秒级完成。 |
| **人工修改** | 1) 加入 `max_states` 上限（200,000）防止极端情况卡死；2) 在副本上搜索，避免污染原棋盘；3) 补充了 4 个单元测试（空盘、单箭头、死锁、多解计数）。 |

## 记录 5：程序化音效合成

| 项目 | 内容 |
|---|---|
| **子任务** | 不依赖外部音频文件，用代码合成游戏音效 |
| **借助何种 AIGC** | Qoder |
| **我提出的要求** | "用 pygame.sndarray + numpy 合成 7 种音效：射出、碰撞、点击、通关、失败、提示、撤销。要求短促、有辨识度、无版权风险。" |
| **AI 实现或提供了什么** | 生成了 `SoundBank` 类，包含 `_tone()`（正弦/方波/三角波）、`_sweep()`（频率扫描）、`_noise()`（白噪声）三个基础波形生成器，以及 7 个具体音效方法。 |
| **实际效果如何** | 初版没有包络（attack/decay），听起来像"哔——"的长音；加入包络后变得短促清脆。numpy 不可用时初版会崩溃，加入 `_HAS_NUMPY` 标志后静默降级为无声模式。 |
| **人工修改** | 1) 给每个音效加入 attack/decay 包络；2) 加入 numpy 可用性检测与降级逻辑；3) 使用懒加载缓存，避免启动时合成所有音效造成卡顿。 |

| 项目 | 内容 |
|---|---|
| **子任务** | 实现"无尽模式"，随机生成可通关的关卡 |
| **借助何种 AIGC** | Qoder |

## 总结

| AIGC 工具 | 主要用途 | 贡献比例（估） |
|---|---|---|
| **Qoder（Coding Agent）** | 代码生成、架构设计、测试编写、文档撰写 | ~85% |
| **ChatGPT** | 算法讨论（DFS 求解器思路） | ~10% |
| **DeepSeek** | 关卡可解性交叉验证 | ~5% |

**AI 带来的帮助：**
- 大幅加速了代码编写，尤其是渲染、动画、音效等"体力活"；
- 提供了算法思路（DFS + 状态去重）；
- 自动生成了大量单元测试，提高了代码质量。

**出现的问题与人工修改：**
- 边界条件处理不严谨（路径检测的负索引）；
- 关卡设计出现死锁（需要人工验证 + 求解器辅助）；
- 动画参数需要人工调优（amplitude、包络、粒子数量）；
- 循环导入问题（需要人工重构为懒加载）。

**自己的收获：**
- 学会了用"求解器 + 单元测试"来验证游戏关卡的可解性，这是一种非常有效的自动化验证手段；
- 理解了 AIGC 的边界：AI 能写出"看起来对"的代码，但边界条件、死锁、性能陷阱仍需要人工审查；
- 掌握了程序化音效合成的基本方法（波形 + 包络 + 缓存）。
